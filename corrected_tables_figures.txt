Figure 3. System Architecture of the Centralized Inventory and Resource Tracking System of LGU Tibiao

Figure 3 shows how the Centralized Inventory and Resource Tracking System of LGU Tibiao processes data from user interaction to database storage. The primary users of the system include the Administrator, Office Head, Supply staff, Accounting staff, and general Staff, each of whom interacts with the system based on assigned access privileges and role-specific responsibilities. The User Interface Layer allows users to access the system through a web-based interface. Through this interface, users can log in, manage asset and inventory records, monitor resource availability, track asset movement, process requisitions, and generate reports. Each interaction made through the interface is processed by the system to perform the required operations. The Application Logic Layer contains the core functional modules that handle system processes. The authentication and authorization module verifies user credentials and controls system access based on role-based access control (RBAC). The asset and inventory management module handles the creation, updating, and monitoring of asset records. The resource tracking module manages the movement, assignment, and status of resources. The requisitions and procurement module manages the workflow for requisition requests, approvals, and procurement tracking. The reporting module generates official LGU reports such as Appendix 73, ICS, PAR, and ITR. The QR code generation module produces property stickers for asset identification. The notification module manages alerts and notification history. The user management module handles user accounts, roles, and permissions. The Data Management Layer stores all system records in Firebase Firestore, including user accounts, asset and inventory data, categories, offices, requisitions, procurement transactions, system logs, access logs, and generated reports. The system also includes an Offline Sync Layer that queues edits made without internet connectivity and automatically synchronizes them to the cloud database once connectivity is restored.

The Entity-Relationship Diagram illustrates the core data structures that support the system's operations. The primary entities include Users, who represent all registered system users with their assigned roles and office assignments; Offices, which represent municipal departments or offices used to classify and assign inventory records; Categories, which group assets by type; and Assets, which store detailed information about each government-owned property including item name, description, property number, quantity, unit, condition, status, and assigned office. Additionally, the ERD includes Requisitions, which track requisition and procurement requests through their lifecycle from submission to approval or decline; Procurement Transactions, which record supplier details, delivery dates, and receiving status for procured items; Notifications, which store alerts and updates for pending approvals and requisition changes; System Logs, which maintain a chronological record of user activities and inventory modifications for audit purposes; and Access Logs, which track user login and access events. These entities are interconnected through defined relationships that support the system's core functions, including inventory management, requisition processing, report generation, and audit trail recording.

Figure 8. Sequence Diagram of Centralized Inventory and Resource Tracking System of LGU Tibiao

Figure 8 shows the interaction among the user, application, authentication module, database, and report generation module. The process begins when the user logs in to the system. The application sends the entered credentials to the authentication module, which verifies the account through the database using Firebase Authentication. Once access is granted, the user can manage asset and inventory records, process requisitions, and generate reports. For asset and inventory management, the user inputs or updates asset details, and the application processes the information and updates the Firestore database accordingly. The system validates all inputs before saving to ensure data accuracy. If the data is valid, the system stores the information and displays a confirmation message. Otherwise, an error message is shown to notify the user of invalid input. For requisitions, the user submits a requisition request, which is forwarded to the appropriate approver (Office Head or Supply). The approver reviews and either approves or declines the request, and the system sends a notification to the requester. When generating reports, the user requests specific data such as inventory status, Appendix 73, ICS, PAR, or ITR. The report generation module retrieves relevant data from the database, formats it according to the selected report type, and presents it to the user for review and printing. The sequence diagram illustrates the systematic flow of operations that ensure data accuracy, real-time updates, and reliable information for municipal operations and decision-making.
